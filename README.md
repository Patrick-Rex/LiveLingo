# LiveLingo

Windows 实时双语字幕工具。采集指定应用的声音，语音识别和翻译分别选择本地模型或 OpenAI 兼容 API，以透明置顶窗口显示可修订字幕。

音频在本机采集。本地模式在本机推理，首次准备依赖和模型需要联网；API 识别发送音频窗口，API 翻译发送原文到所配置服务，服务商可能收费。

## 功能

- 采集指定应用及其子进程的音频，支持目标重启、设备变化与睡眠恢复处理。
- 连续音频缓存、重叠识别和字幕版本控制，显示草稿、修订及积压状态。
- 语音识别和翻译可分别选用本地模型或 OpenAI 兼容 API。识别语言可选中文、英语、日语或韩语，译文统一为简体中文。
- 连续发言分成可修订的短句，无标点的长段也可逐句翻译，译文显示在对应原文下方；字幕支持置顶、鼠标穿透、布局调整及全局快捷键。
- 实时翻译、历史记录和设置三个页面，支持跟随系统、浅色和深色主题。
- 本地保存每次翻译会话，支持查找、复制、TXT / Markdown 导出，以及结束后确认删除和保留期清理。
- 关闭程序时停止采集并回收程序启动的模型进程。
- 启动搜索本机环境，兼容 Ollama 新旧模型清单，缺少依赖时在界面点击安装；发现新版后一次点击完成增量更新和重启。

## 系统要求

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows 11 x64，build 22000 或更高 |
| 应用运行时 | EXE 使用 .NET 10.0 x64 Runtime，缺少时安装器在线补齐；MSIX 自带所需运行时 |
| 本地识别（可选） | 独立 Python 环境和 Qwen 权重，可从设置中按需安装 |
| 本地识别 GPU | 默认使用 CPU；兼容的 AMD Radeon 可选 ROCm，NVIDIA 可选 CUDA 12.8 或 13.0 |
| 翻译来源 | 本地 Ollama / TranslateGemma，或 OpenAI 兼容 API，二选一 |
| 存储 | 任一本机可写盘，可自定义模型、环境、缓存和数据目录 |

模型按需下载。双本地直播会提早识别新语段，本地翻译模型在会话内保持驻留，停止后释放。速度取决于处理器与可用内存；可在设置中选择较小的 TranslateGemma 4B 或单独将某一阶段切换至 API。

## 安装与使用

只需下载一个 [LiveLingo EXE 安装程序](https://github.com/Patrick-Rex/LiveLingo/releases/latest/download/LiveLingo-win-x64-Setup.exe)，双击即可安装并打开程序。缺少 .NET 10 x64 Runtime 时，安装器提示并在线补齐；安装脚本和使用指南已包含在安装包内，不需要另行下载或输入命令。新的普通版本 Release 仅放安装包，增量包和清单放在同仓库的更新专用 Release，用户无需下载。EXE 包不包含 .NET、模型、Python 环境、Ollama 或驱动。

另提供 [MSIX 构建入口](docs/packaging.md#msix-构建)：包含应用所需 .NET 运行时，首次无设置时默认识别和翻译都使用 API，保留切换本地模型的能力并沿用已有配置。当前生成未签名开发包，尚未作为正式安装下载或上架微软商店；MSIX 通过 Windows 安装新包或未来商店更新，不使用应用内 Velopack 更新。

首次安装默认使用 Windows 用户应用目录，从开始菜单启动。新装默认将资源放在当前用户的 %LOCALAPPDATA%\LiveLingoData，可在“设置 → 运行环境”更换路径。升级沿用已有设置和模型。旧 ZIP 迁移和高级安装位置说明见[用户指南](packaging/USER-GUIDE.md)。保留托管安装的 `packages`，后续差分还原需要当前完整包。

在“设置 → 运行环境 → 识别语言”选择音频里说的语言，停止翻译后点击“应用设置”。新安装和旧版自动识别设置默认使用日语，重启后记住上次应用的选择。可在同一页分别选择识别与翻译来源。启动仅为所选本地来源从已配置路径、常用资源目录、PATH 和 OLLAMA_MODELS 搜索环境。在“设置 → 运行环境”点击缺项旁的“安装”，程序执行随包脚本并显示结果，结束后自动复检。选择 GPU 加速时，安装相应厂商的兼容驱动。安装中可取消；已有不兼容模型会报错，不自动覆盖。资源位置需要调整时，使用高级路径配置。

发现新版本后，主窗口和“设置 → 常规”均提供“下载并更新”。停止翻译并应用或撤销设置后，点击一次即可下载、清理退出、安装并自动重启，优先使用差分。未点击时只提示；失败或取消不会退出，之前下载完但未应用的版本显示“安装并重启”。更新保留应用目录之外的模型、设置与历史。

模型配置可用表单或一次导入整体 JSON；识别和翻译在同一文件内配置并一次应用。模板见 [model-config.example.json](packaging/model-config.example.json)，字段与混合模式见[整体模型配置](packaging/USER-GUIDE.md#整体模型配置)。当前 API Key 直接保存在本地设置文件。

| 默认快捷键 | 功能 |
| --- | --- |
| Ctrl+Alt+F7 | 开始 / 停止 |
| Ctrl+Alt+F8 | 显示 / 隐藏字幕 |
| Ctrl+Alt+F9 | 进入 / 退出布局模式 |

点击悬浮字幕右上角的小锁进入布局模式，解锁后显示紧凑拖动条、语言和字号控件。拖动顶部移动，四边四角调整窗口大小；A− / A+ 或 Ctrl+滚轮即时缩放双语文字，普通滚轮查看长句。再次点击小锁恢复正文鼠标穿透；小锁保留独立的40×40 DIP命中区，提示和无障碍名称随锁态变化。位置、尺寸、字号、背景和显示模式即时生效并自动保存，运行中也可调整。

实时页列出所有已识别短句，译文回填到对应原句下方。识别修订后，能按原文和出现次序匹配的短句直接保留译文。变动的短句暂显“上一版 · 待更新”，新译文回填到原位。双语浮窗随刚译好的句对滚动，前面已译的句子可向上回看；仅原文模式直接跟随最新识别。实时页、历史正文和解锁后的浮窗在内容超过窗口高度时显示纵向滚动条。向上回看后，点击“↓ 回到最新”会跳到最新识别的一句，包括还在等译文的句子，并继续跟随新字幕。主窗的按钮同时恢复两处跟随，浮窗的按钮只影响浮窗。回看中重新锁定会保留阅读位置，仍可直接点击返回按钮；正文继续让鼠标穿透到下方应用。显示语言可在“设置 → 字幕外观”或浮窗工具条切换，历史仍保留双语。

设置分为常规、字幕外观、运行环境、快捷键四个内部分组。主题与字幕外观即时生效并自动保存；模型、语言、路径、快捷键和历史保留期停止后点击设置页底部“应用设置”，或用“撤销”放弃未应用输入。切页保留草稿，有待应用设置时不能开始翻译；外观自动保存不会带入运行草稿。

在“设置 → 运行环境 → 翻译词库”可按游戏、作品或场景保存多份原文到简体中文的对照表。词库默认关闭，附有可编辑的游戏与网络用语示例。启用后，整句匹配直接使用指定译文，句中命中的词条随原句提供给模型。每份表可勾选「仅本地翻译使用」，使用翻译 API 时会跳过该表，照常翻译原文。停止后切换词库并应用设置。

历史记录默认保存于数据目录的 `history` 子目录，保留30天，可改为7天、90天或永久。运行中可阅读、复制和导出，结束后可确认删除选中条目、选中会话或全部已结束记录。无条目选择时复制、导出整场，有选择时只处理选中条目；导出固定点击时的内容，保存对话框取消不生成文件。历史保存失败会持续提示并提供重试。

完整步骤见 [安装与模型准备](packaging/USER-GUIDE.md)。两阶段各自只要求所选来源；全 API 无需安装 Python、CUDA、Ollama 或本地权重。

## 从源码构建

需要 Windows 11 x64、.NET 10 SDK（10.0.100 起的稳定功能带及补丁版本）、PowerShell 7 和 Git。源码可放在任意可写目录。`global.json` 使用 `latestFeature`，不要求安装特定的 10.0.4xx SDK，也不自动跨到 .NET 11 或预览版。

普通还原、构建无需先执行环境脚本。NuGet 使用本机配置，默认包缓存为 `%USERPROFILE%\.nuget\packages`；已有 `NUGET_PACKAGES` 等环境变量保持有效。可选的环境脚本默认保留这些设置，显式指定 `-CacheRoot <本机可写绝对路径>` 时才将 NuGet、解包与临时缓存重定向到该目录，仅影响当前终端及其子进程。

```powershell
dotnet restore LiveLingo.slnx --locked-mode
dotnet build LiveLingo.slnx -c Release --no-restore --disable-build-servers -clp:ErrorsOnly
# 存储测试使用本机临时目录。
dotnet test --solution LiveLingo.slnx -c Release --no-build --no-progress
./scripts/New-LiveLingoRelease.ps1 -Version (Read-Host '新的发行版本号') -DownloadPrevious
```

增量发布默认输出到 `artifacts/releases`，固定 Velopack/vpk 1.2.161；同一输出目录保留上一版完整包以生成差分，或使用 `-DownloadPrevious` 获取上一公开版本。示例版本须按实际发布调整，同版本不覆盖。旧 ZIP 打包脚本 `New-LiveLingoPackage.ps1` 仍输出到 `artifacts/packages`，安装目录为 `app\desktop`。完整的打包、包测试、备份、安装替换、核对与回退步骤见 [交付说明](docs/packaging.md)。构建或打包成功不会自动替换已安装程序。

Windows 目标框架中的 `10.0.26100.0` 是编译 API 基线，最低运行平台由 `SupportedOSPlatformVersion=10.0.22000.0` 声明，因此支持 Windows 11 各后续版本。NuGet 库仍按集中版本和依赖锁还原，不随本机 SDK 补丁改变。

从旧配置迁移时，先关闭曾执行旧环境脚本的终端，再开新终端执行 `dotnet restore LiveLingo.slnx --locked-mode --force`，重新生成含本机缓存路径的中间文件。若仍出现旧路径，使用 `dotnet nuget locals global-packages --list` 核对缓存位置，并检查自己设置的 `NUGET_PACKAGES` 或用户级 NuGet 配置。

检查完整编译警告时，使用 `dotnet build LiveLingo.slnx -c Release --no-restore --disable-build-servers -t:Rebuild -warnaserror`；强制重建避免增量构建漏报，并将警告视为失败。测试取消约定见 [测试说明](tests/README.md)。

## 项目结构

| 目录 | 职责 |
| --- | --- |
| `src/LiveLingo.Core` | 音频、字幕、状态机和中立契约 |
| `src/LiveLingo.Runtime` | 连续缓存、识别/翻译调度及持久化 |
| `src/LiveLingo.Platform.Windows` | Application Loopback、Win32 和进程生命周期 |
| `src/LiveLingo.App` | Avalonia 界面与视图模型 |
| `src/LiveLingo.Desktop.Windows` | Windows 桌面入口与依赖组合 |
| `workers` / `runtime-profiles` | Python ASR 工作进程与固定依赖配置 |
| `tests` / `tools` | 回归测试、诊断与评测源码 |
| `scripts` / `packaging` | 构建、安装与依赖准备 |

技术栈：C# 14 / .NET 10、Avalonia、Channels、Microsoft Agent Framework、Qwen3-ASR 和 TranslateGemma。

## 已知限制

- 每场使用一种固定的识别语言。浏览器采集覆盖所选根进程的全部子孙，不能按单个标签页隔离。
- 模型仍可能漏识重复、人名或误译否定。字幕可以继续修订，不能将首次显示视为最终正确结果。
- 首次可读中文通常以3–6秒为目标，首次使用新的模型缓存目录、长句和积压都可能增加延迟。
- 直播优先跟上新语音。持续讲话或前后转写难以衔接时，保留已识别的字幕，从已识别音频的终点分短段继续。跨段处可能断词。某段缩短重试到 2 秒仍无法识别时，标出这段的起止时间，接着翻译后面的讲话。直播中待识别音频积压达到 10 分钟时，程序保留已识别的原文和译文，标明未识别时段，并接着翻译新采集的声音。同一场历史记录可查看缺口。
- 物理混合DPI、显示器拔插及独占全屏的完整兼容性仍需验证。
- 模型准备与安装脚本默认使用D盘布局，可按已应用设置准备模型路径；源码构建与打包不依赖该布局。支持 Windows 安装器与用户确认的增量更新；尚未配置代码签名，首次安装可能显示 Windows 来源提示。
